# RapidInsightStudio — Engineering Memory & Constraints

---

## 1. Architectural Decisions (Must Not Be Reversed Without Explicit Discussion)

1. **Decoupled Two-Phase Pipeline:**
   - *Decision:* LLM seed example rows are generated during schema upload (`POST /schema/upload`) in the background, rather than inside the "Generate Tables" button click.
   - *Rationale:* LLM generation takes 30–60s per table. Running it sequentially on 5–10 tables during button click would cause browser timeouts (>5 minutes). Decoupling keeps the button click fast (~40s).
2. **Explicit SDV Column Typing (Never Use Automatic Detection):**
   - *Decision:* `sdv-service` forbids `Metadata.detect_from_dataframe`. Every column receives an explicit `sdtype`.
   - *Rationale:* SDV's heuristic type detector misclassifies columns named `city`, `name`, `address` as PII and silently replaces them with synthetic faker placeholders (e.g. `Port Brenda`), corrupting the seed data.
3. **Date Ordering Handled Programmatically (Avoid SDV Inequality Constraints):**
   - *Decision:* Dependent dates (e.g., `delivery_date >= order_date`) are excluded from SDV training and calculated post-generation as `order_date + sampled_offset`.
   - *Rationale:* Benchmarks revealed SDV's `inequality` constraint distorts joint probability distributions and slows down generation by 6x due to rejection sampling.
4. **Primary and Foreign Keys Generated by Application Code:**
   - *Decision:* Statistical models never generate IDs or foreign keys.
   - *Rationale:* Statistical models cannot guarantee 100% uniqueness or referential integrity. Primary keys are assigned via counters/UUIDs; foreign keys are sampled directly from already-materialized parent records.
5. **Gateway as Sole Ingress:**
   - *Decision:* All client traffic routes through Gateway (`PORT 3000`). Internal microservices require `x-internal-service-key` and reject direct external requests.
   - *Rationale:* Enforces unified JWT validation, rate limiting, and protects sensitive AI API keys stored in `ai-service`.

## 2. Platform & Environment Constraints

1. **Python Environment & Windows Path Limitations:**
   - *Constraint:* Windows enforces a 260-character path limit (`MAX_PATH`). PyTorch dependencies contain deeply nested licensing paths (~13 levels).
   - *Resolution:* On Windows, virtual environments must be installed in `C:\sdvenv` or with `LongPathsEnabled = 1`. On Linux/macOS, `.venv-sdv` or `~/.sdvenv` is used.
2. **Node.js Environment:**
   - *Requirement:* Node.js v20+ with native ES modules support for frontend (Vite) and CommonJS for backend services.
3. **Database Architecture:**
   - *Requirement:* PostgreSQL instance (Supabase) with support for dynamic schema provisioning (`CREATE SCHEMA org_project`) and cascading teardowns.

## 3. Conventions & Standards

1. **Naming Conventions:**
   - Database schemas: `<org_sanitized>_<project_sanitized>` (lowercase alphanumeric with underscores).
   - Physical table names: sanitized snake_case matching schema entity names.
   - API endpoints: Plural resource nouns, RESTful verbs (e.g., `/projects`, `/schemas`, `/tables`).
2. **Headers:**
   - External requests: `Authorization: Bearer <supabase_jwt>`
   - Internal microservice proxying:
     - `x-user-id`: Authenticated user UUID
     - `x-user-email`: Authenticated user email
     - `x-request-id`: Distributed trace UUID
     - `x-internal-service-key`: Shared internal cluster secret

## 4. Known Issues & Tech Debt Log

- **Issue #1 (Frontend useAuth contract mismatch):**
  - *Symptom:* Legacy pages (`SchemaUploadPage`, `MySchemasPage`, `StoragePage`, `WorkspacePage`, and legacy `Sidebar`) called `getAccessToken`, `signOut`, or `user` from `useAuth()`, which `AuthContext` did not expose.
  - *Resolution:* Add compatible aliases (`getAccessToken`, `signOut`, `user`) to `AuthContext.jsx` to prevent runtime crashes on any route.
- **Issue #2 (Frontend supabaseClient startup crash):**
  - *Symptom:* `src/lib/supabaseClient.js` threw an unhandled error at import time if `VITE_SUPABASE_URL` was not defined in `.env`.
  - *Resolution:* Initialize client safely or configure proper `.env` fallback to avoid white-screen crashes before login.
- **Issue #3 (Stub Services):**
  - *Detail:* `report-service` (`PORT 3004`) and `export-service` (`PORT 3009`) are health-check skeletons. Active logic currently resides in `table-service` and `project-service`.
